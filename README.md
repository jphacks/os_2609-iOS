# AR ダンジョン（iOS）

屋内の会場を歩き回りながらモンスターを集めて戦う AR ゲーム「AR ダンジョン」の iOS アプリ。
プロダクト全体の説明は [jphacks/os_2609](https://github.com/jphacks/os_2609) の README にある。

## 製品概要
展示会や学園祭などの屋内イベントでは、来場者が入口付近や目当てのブースだけを見て帰ってしまい、会場全体を歩いてもらうのは難しい。
「AR ダンジョン」は、歩くこと自体を楽しくして、会場を回るきっかけを作る。屋内では GPS が届かないので、カメラで測る移動距離と、会場に置いた BLE ビーコンを使う。

### できること
* 最初に 3 体から相棒を 1 体選んでスタートする
* 会場を歩くと、カメラに映る床の上にモンスターが現れる（歩いた距離で出現するので、GPS がいらない）
* モンスターをタップするとバトルが始まる。画面をタップして攻撃し、スワイプで必殺技をよける。勝てば捕まえられる
* 捕まえたモンスターは図鑑に記録され、編成でバトルに出す相棒を選び直せる
* 目の前にいるプレイヤーと BLE で見つけ合い、その場でリアルタイムに対戦できる（Android 版とも対戦できる）
* 会場マップで、自分が今どのチェックポイントにいるかがわかる（会場に置いた BLE ビーコンの電波の強さから推定する）

### 特長
#### 1. 屋内でも、歩くほどモンスターに出会える
GPS を使わず、ARKit がカメラで測る端末の移動距離でモンスターを出すので、屋内のどこでも遊べる。
会場に置いた 6 台のビーコンの電波の強さの組み合わせから、どのチェックポイントにいるかを推定してマップに表示する。歩いている間の揺れた電波は使わず、立ち止まったときに測ることで推定を安定させ、推定の信頼度も表示する。

#### 2. タップとスワイプだけで熱くなれる AR バトル
カメラに映る床の上で、3D のモンスター同士が戦う。画面をタップして攻撃し、必殺技の予告が出たらスワイプでよける。
攻撃しすぎるとスタミナが切れて休憩になり、フィーバーやチャンスの演出が駆け引きを生む。攻撃が当たった瞬間のヒットストップや振動で、手応えを出している。

#### 3. 目の前にいる人とだけ対戦できる
対戦の受付を ON にすると、近くの端末どうしが BLE で見つけ合い、電波が一番強い（一番近い）相手が候補に出る。お互いが「対戦する」を選ぶと、サーバーがその 2 人だけを組み合わせるので、遠くのプレイヤーとはつながらない。会場で出会った人と、その場で対戦できる。

### 注力したこと
* **AR を安定して動かすこと**：捕獲とバトルで AR を切り替えると、画面が真っ黒になったり、床にモンスターを置けなくなったりした。原因は RealityKit の画面が同時に 2 つあることだったので、AR の画面は常に 1 つにし、カメラ映像のない 3D は SceneKit で描く形にした。捕獲からバトルへは AR セッションを引き継ぎ、床を探し直さずに、野生のモンスターがいた場所でそのまま戦える
* **屋内の位置推定を安定させること**：加速度センサーで歩いているかを見分け、立ち止まってから集めた電波だけで推定する。現在地が決まったらしばらく保持して飛びにくくし、推定の信頼度も出す
* **Android 版と同じ体験にそろえること**：同じ 16 体のモンスター、同じバトルのルール、同じデータベースと近接対戦のしくみを使い、OS が違っても対戦できるようにした

## 開発技術
### API・データ
* Supabase：マルチバトル。近くの相手の確保と双方の承諾、対戦の部屋づくりは Postgres の関数（RPC）、攻撃などのやり取りは Realtime の変更通知で送り合う。Android 版と同じデータベースを使う
* Core Bluetooth：ビーコンの電波の強さ（RSSI）を受け取る。近くで対戦を受け付けている端末を見つける
* Core Motion：歩いているか、立ち止まっているかを見分ける
* CryptoKit：ビーコンの電波に付いた署名（HMAC-SHA256）を確かめる
* SwiftData：捕まえたモンスターとバトルに出すモンスターを端末に保存する

### フレームワーク・ライブラリ・モジュール
* SwiftUI、ARKit、RealityKit（AR の中の 3D）、SceneKit（カメラ映像なしの 3D と図鑑の画像）、supabase-swift
* ビーコン：Arduino（ESP32、Raspberry Pi Pico W のファームウェア。`firmware/`）
* 3D モデル：Quaternius「Ultimate Monsters」（CC0 のフリー素材）。Blender のスクリプト（`scripts/convert_monster_models.py`）で USDZ に変換し、14 種類のアニメーションを 1 本にまとめた（アプリ側で区間を切り出して流す）

### デバイス
* iPhone 15（デモ機）
* BLE ビーコン 6 台：ESP32 × 3、M5Stack（ESP32-S3）× 1、Raspberry Pi Pico W × 1、Raspberry Pi Pico 2 W × 1

## ビルド方法
1. `ARApp.xcodeproj` を Xcode で開く。デプロイメントターゲットは iOS 26.2
2. 署名：`Config/Signing.xcconfig.local.example` をコピーして `Config/Signing.xcconfig.local` を作り、自分の Team ID と Bundle ID の接頭辞を書く
3. 対戦の接続先：`supabase/SupabaseSecrets.example.plist` をコピーして `ARApp/Resources/SupabaseSecrets.plist` を作り、Supabase の URL と anon キーを書く（書かなければ CPU が相手になる）。テーブルと関数は `supabase/schema.sql`
4. iPhone を接続して実行する。AR は実機でだけ動く（シミュレータでは「ARに対応していません」と出る）

ビルドだけを確かめるときは次のコマンドを使う。

```sh
xcodebuild -project ARApp.xcodeproj -scheme ARApp -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
```
